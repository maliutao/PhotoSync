# 通信协议 v1（手机 ↔ 电脑）

手机端与电脑端通过局域网 HTTP 通信。所有请求携带请求头 `X-Token: <令牌>`；令牌错误一律返回 `401 {"error":"bad token"}`（包括 `/ping`——手机端用「401」与「网络超时」区分"令牌不正确"和"电脑不在线"两种提示）。

## 自动发现（UDP 广播，可选配对方式）

电脑端接收软件运行期间，每 2 秒向 `255.255.255.255:52000/UDP` 广播：

```json
{"app": "photo-sync-receiver", "version": 1, "hostname": "DESKTOP-XXX",
 "port": 8765, "devices": {"手机A": "<令牌>", "手机B": "<令牌>"}}
```

手机端「设置 → 搜索电脑」监听该端口约 3.5 秒，列出所有正在运行的电脑；选中后选择本机身份（手机A/手机B），IP/端口/令牌自动填入。广播包含令牌（明文）——与 v1 局域网明文 HTTP 同一信任模型。手机仍可手动填 IP，两种方式并存。

## key（文件在电脑端的相对路径）

`清洗(相册目录名)/YYYY/MM/清洗(文件名)`，整体 URL 编码传输。

- 清洗规则（手机端生成时执行，电脑端校验时兜底）：`<>:"/\|?*` 及控制字符替换为 `_`；去除首尾空白与尾部 `.`；每段 ≤128 字符。
- 年月取自 `DATE_MODIFIED`（与指纹口径一致；编辑导致跨月时文件会归入新月份目录）。
- 电脑端实际存盘路径：`保存根目录/<设备名>/<key>`，即 `保存根/设备名/相册/年/月/文件名`。

## 同名冲突与去重（两端共同遵守的命名算法 resolve_final）

同目录同名但 `size` 或 `mid`（mediaId）不同的文件视为不同内容（例如照片被编辑后的新版本）。候选文件名依次为：

```
原名.ext → 原名_m<mediaId>.ext → 原名_m<mediaId>_2.ext → …
```

- 第一个「已存在且磁盘大小 == size」的候选 → 判定已存在（去重命中）；
- 否则第一个「不存在」的候选 → 本次保存位置。**绝不覆盖磁盘上大小不同的同名文件**。

因此：手机端编辑照片后重传，电脑端会出现 `IMG_0001_m87.jpg` 之类的新版本，原备份不动；因 mediaId 确定，重传/重装 App 去重结果稳定，不会产生第三份。

## 接口

| 方法 | 参数 | 成功响应 | 错误码 |
|---|---|---|---|
| `GET /ping` | 无 | `200 {"app":"photo-sync-receiver","version":1}` | 401 |
| `GET /status` | `key`、`size`、`mid` | `200 {"exists":bool,"free":字节,"reserve":字节}` | 400 / 401 |
| `PUT /upload` | `key`、`total`、`mid`；body 为原始字节流，`Content-Length == total` | `200 {"saved_as":相对路径,"dedup":bool}` | 400 / 401 / 504 / 507 / 500 |

- `free` / `reserve`：电脑端保存目录所在磁盘的剩余空间与保留空间（默认 5GB）。手机端据此预判 `free < size + reserve` 时主动停止并给出明确提示；`/upload` 前电脑端也会强制检查，不满足返回 **507**（Insufficient Storage），手机端收到后停止整个同步。
- `dedup: true` 表示电脑端已有同名同大小完整文件，本次未写盘（body 未被读取，连接随即关闭）。
- 接收语义（电脑端实现要点）：
  - 临时文件 `正式名.<6位随机>.part`，边收边写（64KB 块）；
  - 连续 **30 秒无任何字节到达** → 504，删除临时文件；只要数据持续到达，不论文件多大、总耗时多长都不会触发；
  - 收满且大小 == total 后 `fsync` 并原子改名为正式文件；
  - 任何失败（超时 / 对端断开 / 磁盘写满 / 电脑关机）都会或将由启动清理删除 `.part`——正式目录里的文件一定是完整的；
  - 软件启动时递归删除保存目录下所有遗留 `.part`。

## 手机端上传约定

- 上传分块 512KB，流式读取（`openInputStream` 在上传前一刻打开、传完立即关闭，不跨文件持有流）。
- 每个文件上传成功后立即写入本地 Room 数据库（`mediaId + size + dateModified` 指纹）；下次开始时做「相册清单 − 已完成记录」差集，只传剩余。
- 被中断的文件作废重传（v1 无断点续传）。
- 收到 507 / 401 / 网络异常 → 停止整个同步批次并给出对应提示。
